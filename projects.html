02 / MY PROCESS

What goes into a strong analysis?

A data project starts with a question, not a chart. Before opening a dataset, I try to think about what the information represents and what someone might learn from it. A useful question should be specific enough to explore, but open enough to reveal something new. For example, a project about transactions might ask which categories appear most frequently or how spending changes over time. Questions like these influence how the dataset needs to be organized and what kinds of visual comparisons will be meaningful.

Next comes preparation. Real-world data may contain duplicate rows, missing values, inconsistent labels, or values stored in the wrong format. Cleaning those issues makes later analysis more reliable. Exploratory data analysis is where I summarize distributions, look for patterns, and check for unusual observations. I am learning to use Python and plotting tools for this work, while also experimenting with web-based visualization through D3.js. Different tools offer different advantages, and selecting the right one depends on the purpose of the project.

The final step is communicating the result responsibly. Charts should include useful labels, readable colors, and enough context for readers to understand what is being compared. A result also needs an explanation of its limitations. For example, the D3 chart on this page uses fictional sample data because its purpose is to demonstrate interactive web visualization rather than to report an actual research finding. My goal is to develop a habit of showing my methods clearly, being honest about uncertainty, and making a project easy for others to follow.

My analysis checklist

  • Define a useful question and understand the dataset.
  • Check data quality and clean inconsistencies.
  • Explore the data with summary statistics and charts.
  • Explain what the results show and what they do not show.
  • Communicate findings with accessible visualizations.
